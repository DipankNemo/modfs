import json
import subprocess

def run_cmd(cmd, check=True):
    print(f"--> Running: {' '.join(cmd)}")
    subprocess.run(cmd, check=check)
 
def build_module(spec_path):
    # 1. Load Specification
    with open(spec_path, 'r') as f:
        spec = json.load(f)
    
    name = spec['name']
    distro = spec['distro']
    packages = spec['packages']
    
    chroot_dir = f"/srv/baas/build/chroot/{name}"
    sqsh_out = f"/srv/baas/modules/artefacts/{name}.sqsh"
    pkg_list_out = f"/srv/baas/modules/artefacts/{name}_packages.txt"
    meta_out = f"/srv/baas/modules/artefacts/{name}.json"
 
    print(f"\n=== Building Module: {name} ===")
 
    # 2. Run debootstrap if directory doesn't exist
    if not os.path.exists(f"{chroot_dir}/bin"):
        run_cmd(["sudo", "debootstrap", distro, chroot_dir])
    else:
        print("--> Base filesystem already exists, skipping debootstrap.")
 
    # 3. Safely Mount, Install, and Unmount
    try:
        # Mount critical virtual filesystems safely
        run_cmd(["sudo", "mount", "--bind", "/dev", f"{chroot_dir}/dev"])
        run_cmd(["sudo", "mkdir", "-p", f"{chroot_dir}/dev/pts"])
        run_cmd(["sudo", "mount", "-t", "devpts", "devpts", f"{chroot_dir}/dev/pts"])
        
        # Install packages inside chroot
        pkg_string = " ".join(packages)
        chroot_cmd = (
            f"apt-get update && "
            f"DEBIAN_FRONTEND=noninteractive apt-get install -y {pkg_string} && "
            f"dpkg-query -W -f='${{Package}}=${{Version}}\\n' > /packages.txt"
        )
        run_cmd(["sudo", "chroot", chroot_dir, "/bin/bash", "-c", chroot_cmd])
        
        # Copy out the package list
        run_cmd(["sudo", "cp", f"{chroot_dir}/packages.txt", pkg_list_out])
        
    finally:
        # GUARANTEED CLEANUP: Always unmount children before parents
        print("--> Cleaning up mounts...")
        run_cmd(["sudo", "umount", "-l", f"{chroot_dir}/dev/pts"], check=False)
        run_cmd(["sudo", "umount", "-l", f"{chroot_dir}/dev"], check=False)
 
    # 4. Generate Metadata file
    with open(meta_out, 'w') as f:
        json.dump(spec, f, indent=2)
    print(f"--> Saved metadata to {meta_out}")
 
    # 5. Build SquashFS (excluding virtual dirs just to be ultra-safe)
    if os.path.exists(sqsh_out):
        run_cmd(["sudo", "rm", "-f", sqsh_out])

        "sudo", "mksquashfs", chroot_dir, sqsh_out,

    ]

    print(f"\n=== SUCCESS: Module {name} built at {sqsh_out} ===")

This is the most critical question of your entire bachelor thesis. Your professor specifically highlighted dependency management as the core academic challenge. 
 
If you just blindly smash two filesystems together, things will eventually break. To manage this, we must divide "conflicts" into two entirely different categories because they happen at two different levels: File-Level Conflicts and Package-Level Conflicts.
 
Here is exactly what they are and how your automated BaaS architecture will manage them.
 
 
Type 1: File-Level Conflicts (The OverlayFS Collision)
 
This conflict happens when two different modules contain the exact same file path (e.g., both modules have a file named /etc/environment).
 
The Conflict: If base.sqsh has a default /etc/hosts file, and machine_node1.sqsh has a custom /etc/hosts file, which one does the final OS use?
The Management Strategy: Strict Layer Ordering.
  You do not need to write complex Python code to solve this because OverlayFS handles it natively. OverlayFS uses a strict hierarchy. If two layers have the same file, the layer mounted "higher" automatically wins and hides the file from the "lower" layer.
How we do it: We enforce a strict priority rule in our compose_image.py script. Base Module is always at the absolute bottom.
Project Modules (like CUDA) sit in the middle.
Machine Modules (hostnames, IP configs) sit at the absolute top.
 
If a Project module needs to overwrite a Base configuration file, it just does it automatically by sitting physically higher in the OverlayFS stack.
 
 
Type 2: Package-Level Conflicts (The APT Dependency Collision)
 
This is the dangerous type of conflict, and solving this is what gets you a great grade on your thesis. 
 
The Conflict: * Your base module installs libc6 version 2.31.Your cuda_project module requires libc6 version 2.35.
OverlayFS will just stack them. The final OS will boot, but the /var/lib/dpkg/status (APT's internal database) will be completely corrupted because the Base OS thinks v2.31 is installed, but the CUDA layer overwrote the actual binary files with v2.35. If the user runs apt upgrade on the node, the OS will shatter.
 
 
The Management Strategy: The Union Simulation.
  We cannot let OverlayFS merge broken package dependencies. We must mathematically prove the combination is safe before we mount OverlayFS.
 
How we automate the Dependency Check:
 
Remember how our build_module.py script created a packages.txt file (e.g., base_packages.txt and cuda_packages.txt)? We use those files to build an automated conflict checker.
 
Before compose_image.py is allowed to run, we run a validation step:
 
Compute the Union: The Python script reads base_packages.txt and cuda_packages.txt and strips out the version numbers, creating a giant master list of every package required across all modules.
The Clean Room Simulation: The script creates a temporary, empty debootstrap chroot (a "Clean Room").
The APT Solver: The script runs a dry-run command inside the clean room: 
apt-get --simulate install <master_list_of_all_packages> 
The Verdict:If apt returns Exit Code 0, it means Ubuntu's official package solver guarantees these packages can coexist without breaking each other. Conflict avoided. Proceed to OverlayFS.
If apt returns an error (e.g., "held broken packages" or "version conflict"), it means the modules are fundamentally incompatible. The script halts and refuses to build the image.

To implement this, we will write a script (or add a function to compose_image.py) that acts as the Dependency Validator.

def validate_dependencies(module_list):
    master_package_list = set()
    
    # 1. Read all the packages.txt files from the requested modules
    for mod in module_list:
        with open(f"/srv/baas/modules/artefacts/{mod}_packages.txt", 'r') as f:
            for line in f:
                # Split "package=version" and just keep the package name
                pkg_name = line.split('=')[0].strip()
                master_package_list.add(pkg_name)
                
    # 2. Run the APT simulation in a clean environment
    pkg_string = " ".join(master_package_list)
    sim_cmd = f"apt-get update && apt-get --simulate install {pkg_string}"
    
    print("--> Running APT Dependency Conflict Checker...")
    result = subprocess.run(["sudo", "chroot", "/srv/baas/build/chroot/clean_test_room", "/bin/bash", "-c", sim_cmd], capture_output=True)
    
    # 3. Handle the Conflict
    if result.returncode == 0:
        print("--> No dependency conflicts found. Safe to compose image.")
        return True

def validate_dependencies(module_list):
    print("\n--> Validating Dependencies across all modules...")
    master_package_list = set()
    
    for mod in module_list:
        pkg_file = f"/srv/baas/modules/artefacts/{mod}_packages.txt"

        with open(pkg_file, 'r') as f:
            for line in f:
                if '=' in line:

                    master_package_list.add(pkg_name)

    clean_room = "/srv/baas/build/chroot/clean_test_room"
    if not os.path.exists(f"{clean_room}/bin"):

        run_cmd(["sudo", "debootstrap", "jammy", clean_room])
        
    pkg_string = " ".join(master_package_list)
    sim_cmd = f"apt-get update && apt-get --simulate install {pkg_string}"
    
    print("--> Running APT dry-run simulation...")
    result = subprocess.run(["sudo", "chroot", clean_room, "/bin/bash", "-c", sim_cmd], capture_output=True, text=True)

        print("--> VALIDATION SUCCESS: No dependency conflicts found.")
        return True
    else:
        print("!!! FATAL DEPENDENCY CONFLICT DETECTED !!!")
        print(result.stderr)
        return False

def run_cmd(cmd, check=True):

def pack_disk(image_name):
    print(f"\n=== Packing Disk for: {image_name} ===")
    
    merged_dir = f"/srv/baas/build/overlay/{image_name}/merged"
    img_out = f"/srv/baas/images/artefacts/{image_name}.img"
    mnt_node = f"/mnt/{image_name}_root"
 
    if not os.path.exists(merged_dir):
        print(f"!!! Merged directory {merged_dir} not found. Run compose_image.py first.")
        sys.exit(1)
 
    # 1. Create and Partition the raw image
    run_cmd(["qemu-img", "create", img_out, "8G"])
    run_cmd(["sudo", "losetup", "-f", img_out])
    
    # Find the loop device it attached to
    losetup_out = run_cmd(["sudo", "losetup", "-a"]).stdout
    loop_dev = None
    for line in losetup_out.splitlines():
        if img_out in line:
            loop_dev = line.split(":")[0].strip()
            break
            
    if not loop_dev:
        print("!!! Failed to find attached loop device.")
        sys.exit(1)
        
    print(f"--> Image attached to {loop_dev}")
 
    try:
        run_cmd(["sudo", "parted", loop_dev, "--script", "mklabel", "msdos"])
        run_cmd(["sudo", "parted", loop_dev, "--script", "mkpart", "primary", "ext4", "1MiB", "100%"])
        
        # 2. Map partitions using kpartx (Robust method)
        run_cmd(["sudo", "kpartx", "-av", loop_dev])

If you JIT-compile the Base, CUDA, and Web Server modules at the exact same time you run the simulation, they will physically download those exact same latest libraries. Then, when OverlayFS merges them, everything fits together perfectly like puzzle pieces because they all share the exact same dependency tree.
 
You have completely grasped the hardest academic concept of this thesis. If you explain this exact flow to your professor—how you decouple the physical file merge (OverlayFS) from the logical dependency validation (APT Simulation), and secure it with JIT Compilation—they will be extremely impressed.
