# 8 Conclusion and future work

ModFS explores whether ordinary Ubuntu package installations can become reusable sibling filesystem deltas for Bare Metal as a Service. The answer is conditional. A fixed archive snapshot and an exact shared base make the siblings comparable; an OverlayFS upperdir captures each installation's changes; SquashFS stores them compactly; admission excludes known incompatible sets; and a reconciliation layer combines shared system state before a selected root is flattened. The result retains mainstream APT/dpkg packages and filesystem paths. It does not require a modular root on the provisioned node.

The first contribution is a conflict taxonomy tied to a policy for each mechanism. Benign overlap may be accepted; version, relation, and unsanctioned path conflicts are rejected; base drift, identity collision, and opaque-directory erasure are prevented during building; unowned system registries are reconciled or regenerated; service resource conflicts require a running system to observe. The distinction matters because one generic “file collision” check cannot detect lost dpkg records, a borrowed UID, an opaque directory that hides a sibling, or competing listeners. The eight registry groups and their record rules make the shared-state portion of the taxonomy implementable rather than only descriptive.

The current 40-module catalogue supplies an exhaustive static result: 667 of 780 pairs and 7,807 of 9,880 triples were admitted (`thesis/evidence/tier1.md` T1.1). The intentionally incompatible control was rejected wherever it appeared, and accepted triples containing a rejected pair demonstrate why module requirements cannot be turned blindly into pairwise exclusion edges (`tier1.md` T1.4–T1.5). The repository storage comparison is 1.84× for all 40 modules, 5.43× for its small adversarial cohort, and 1.20× for its large cohort (`thesis/evidence/storage.md` S1). Those are server-side ratios for this catalogue, using a monolithic $B+d$ model calibrated by six actual whole-root builds; they are not a per-node transfer result.

The verification result is more informative than an unqualified clean-pass statement. Repeated adversarial reviews found predicates that passed while observing too little, and harnesses whose own behavior constrained the measurement. The regression tests preserve these counterexamples. The retained physical sweep predates rebuilt artefacts, so its clean V1–V8 rows and its cost fits are historical; the generated evidence withholds a current tier-2 table (`thesis/evidence/tier2.md`). Most boot bundles are also superseded. Earlier boots did expose the nginx/Apache runtime conflict, while a still-current GPU-stack bundle establishes a successful guest boot without GPU hardware (`tier3.md`). Thus the thesis demonstrates a method and a set of bounded observations, not current full-catalogue boot reliability.

The next step is to rerun physical compositions and representative boots against the exact artefacts now published, with every result naming its catalogue and generation. The visibility assertion should be extended to detect equal-size content substitutions on paths whose bytes matter. Independent rebuilds and generation publication need separate work: snapshot pinning fixes package resolution but did not make artefacts byte-identical across machines, while a transactional catalogue publisher and remote transfer client are not implemented. Testing the packaged NVIDIA driver with real GPU access and its matching kernel would close a different claim from userspace CUDA execution. Finally, a deployment trial should measure whole-image transfer, rollback, and long-lived node behavior rather than projecting server repository savings onto them.

The central conclusion is methodological. Modular images are useful only when compatibility is defined at the level of the system being delivered. Package metadata, filesystem names, shared registries, and running services expose different facts. ModFS's strongest result is the explicit boundary between those facts, and the verification record shows how easily a clean check can overstate what it has seen.
